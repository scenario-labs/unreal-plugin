# unreal-plugin: agent instructions

Root `AGENTS.md` is the repository rulebook; `.claude/CLAUDE.md` links here.
[README.md](README.md) describes the plugin for users; the handbook is in
[docs/](docs/).

## What this repository is

Scenario for Unreal Engine: an Unreal Editor plugin for Unreal 5.6 to 5.8,
C++ only, in `Plugins/Scenario/`. It prices and runs every Scenario model and
workflow through the hosted Scenario MCP (`https://mcp.scenario.com/mcp`:
JSON-RPC 2.0 over HTTP, SSE or JSON replies, OAuth or an API key and secret),
imports the results as native assets and places them in the open level. People
drive it from the Studio tab and the viewport composer; agents drive it through
a local MCP server inside the editor.

The repository root is a small host project (`ScenarioHost.uproject`, module
`Source/ScenarioHost`) used to build and test the plugin. A release zip holds
`Plugins/Scenario/` alone. Nothing from the plugin is compiled into a packaged
game: every module is `Type: Editor`.

## Code map

`Plugins/Scenario/Source/`:

- `ScenarioCore/` (loading phase Default; no editor API, unit-tested):
  - `ScenarioMcpClient`: the backend interface and its hosted Scenario MCP
    implementation; read and submit tool lists, retry policy (reads and dry
    runs only), `SCENARIO_NO_SPEND`.
  - `ScenarioRpc`, `ScenarioHttp`: JSON-RPC framing, SSE or JSON replies, the
    HTTP transport on top of Unreal's HTTP module.
  - `ScenarioApi`: typed calls (models, schemas, prices, jobs, assets,
    workflows, usage); CU values carried as exact decimal strings.
  - `ScenarioSession`: sign-in state, workspace (team and project), price
    checks, paid runs, polling, downloads. Every caller goes through it, so the
    money rules hold for the Studio, the composer, agents, scripts and the
    commandlet alike.
  - `ScenarioQuotes`: single-use quotes and their fingerprints.
  - `ScenarioLedger`: the durable job list in `<Project>/Saved/Scenario/`,
    intent rows, Unknown state, reconciliation.
  - `ScenarioTransfer`: resumable downloads (`.part` files), presigned uploads,
    host allow-lists.
  - `ScenarioOAuth`: browser sign-in with PKCE on a loopback port, device code
    fallback, token refresh.
  - `ScenarioCredentialStore` (+ `Private/Platform/`): macOS Keychain, Windows
    Credential Manager, otherwise an owner-only file in the user's config
    folder.
  - `ScenarioLocalHttpServer`: the loopback HTTP listener used by OAuth and by
    the agent server.
  - `ScenarioSchema`: model schema to form fields, validation, payloads.
  - `ScenarioCatalog`, `ScenarioLanes`: the model picker's catalog (cached 24
    hours) and the lanes read from `Resources/Lanes.json`.
  - `ScenarioFiles`, `ScenarioJson`, `ScenarioHash`, `ScenarioCU`,
    `ScenarioErrors`, `ScenarioTypes`: naming and type sniffing, defensive JSON
    and canonical JSON, SHA-256, CU formatting, error kinds and messages.
  - `ScenarioTelemetry`: opt-in usage events, silent while no collection
    endpoint is set (none in 0.1); fields listed in `docs/PRIVACY.md`.
  - `ScenarioFakes`: fake transport and fake Scenario used by the tests.
  - `Private/Tests/`: automation tests `Scenario.Core.*`.
- `ScenarioEditor/` (loading phase PostEngineInit):
  - `ScenarioEditorModule`: menus, toolbar button, Studio tab, composer,
    context menus, toasts.
  - `ScenarioSubsystem`: editor subsystem that owns the session, imports and
    placements; returns what each action changed.
  - `ScenarioAssets`, `ScenarioPlacement`: import per kind (Interchange for
    meshes, textures with per-role settings, sounds, media, skies) and placement
    in the level, one undo transaction each.
  - `ScenarioProvenance`: `Scenario.*` metadata on every imported asset and the
    index behind the "Generated by Scenario" Content Browser filter
    (`ScenarioContentBrowserFilter`).
  - `ScenarioSettings`: Editor Preferences > Plugins > Scenario.
  - `Actions/`: the action registry shared by agents, Blueprints, Python and the
    commandlet (`ScenarioActions`, `ScenarioScenarioActions`,
    `ScenarioLevelActions`, `ScenarioOutputLog`).
  - `ScenarioScriptLibrary`: Blueprint and Python entry points (start and poll,
    plus the async node "Run Scenario Action").
  - `ScenarioCommandlet`: `-run=Scenario` for scripted generations.
  - `UI/`: Slate views: Studio, Create page, model picker, forms, job cards,
    Jobs, Library, Workflows, Connection, sign-in, viewport composer, style and
    thumbnails.
  - `Private/Tests/`: automation tests `Scenario.Editor.*` (action registry,
    imports, placement undo, provenance, Studio registration).
- `ScenarioAgent/` (loading phase PostEngineInit):
  - `ScenarioMcpServer`: the local MCP server (Streamable HTTP on
    `127.0.0.1:9877` or the next free port, bearer token, Host and Origin
    checks, sessions, tool annotations).
  - `ScenarioAgentClients`: Connect buttons for Claude Code, Codex, Cursor and
    Claude Desktop, with a timestamped backup of every config file they edit.
  - `ScenarioAgentModule`, `SScenarioAgentsSection`: server lifecycle, token,
    activity log, Connection > Agents.
  - `Private/Tests/`: automation tests `Scenario.Agent.*`.

Also in `Plugins/Scenario/`: `Resources/Lanes.json` (lanes, picks, presets),
`Resources/AgentSkill/SKILL.md` (the agent skill the Connect section installs),
`Tests/Fixtures/` (recorded Scenario replies), `Config/FilterPlugin.ini`.

## Spending rules

Every change keeps them. They are enforced in `FScenarioSession` and
`FScenarioMcpClient`, below every caller.

1. A price check is a dry run (`model_run` or `workflow_run` with
   `dry_run: true`). It is free and returns the exact CU cost.
2. Generate needs an unused quote whose fingerprint matches the request now
   (SHA-256 of target, workspace and canonical JSON) and consumes it. Quotes
   expire after 120 seconds. Agents pass `quote_id` and `approved_cost` equal
   to the quote's exact CU string.
3. The intent row is written to the job list before the paid request. If it
   cannot be written, nothing is sent.
4. A paid call is sent once. Any tool not known to be a read is treated as
   able to spend and is never retried. A transport failure on it marks the job
   Unknown, which blocks an identical request until it is reconciled.
5. `SCENARIO_NO_SPEND=1` refuses paid calls before any request; `job_cancel`
   still goes out.
6. Secrets live in the OS credential store only: never in project config,
   `Saved/`, logs, provenance or error messages.

## Commands

The engine is found through `$UE_ROOT` (default
`/Users/Shared/Epic Games/UE_5.8`). Engine builds and tests run on a Mac with
Unreal installed; GitHub-hosted runners have no engine.

```sh
tools/build.sh                 # RunUAT BuildPlugin into Build/Scenario-<version>-UE<x.y>
tools/build.sh --host          # also builds the ScenarioHostEditor target
tools/test.sh [filter]         # automation tests headless (default filter: Scenario)
python3 tools/lint.py          # headers, em dashes, JSON files, skill frontmatter, secrets
python3 -m unittest discover -s tools/tests   # tests of the Python tools
uv run --no-project --with markdown==3.10.3 python tools/build_site.py --output <dir>
python3 tools/contract_check.py               # free live check, needs a test key
```

`tools/contract_check.py` sends reads and dry runs only and refuses paid tools
itself. It needs `SCENARIO_API_KEY` and `SCENARIO_API_SECRET` (or
`SCENARIO_KEYCHAIN_SERVICE` on macOS). Any paid run needs explicit
authorization for the project and budget first.

## CI

| Workflow | When | What |
| --- | --- | --- |
| `ci.yml` | pull requests, `main` | `lint`, `tools` (Python tests), `site` (docs build); `ci-ok` requires all three |
| `contract.yml` | weekly, PRs changing `ScenarioCore/` or the tool | `tools/contract_check.py` with `SCENARIO_NO_SPEND=1`, 0 CU (test key secrets; skipped with a warning without them) |
| `links.yml` | weekly, docs PRs | links in Markdown (except the generated `CHANGELOG.md`) |
| `pages.yml` | `main` when docs change | builds the docs site and deploys it to GitHub Pages |

No engine build runs on GitHub. Before a release, `tools/build.sh` and
`tools/test.sh` run on a Mac with each supported engine version.

## Rules

- Every `.h`, `.cpp` and `.cs` file starts with
  `// Copyright (c) 2026 Scenario Inc. Licensed under the MIT License.`
- No em dashes, in code, docs, commit messages and PR titles.
- This repository is public: no credentials, session IDs, personal paths,
  team, project, job or asset ids, account records, machine details or spend
  anecdotes in code, docs, commits or PRs.
- No code from `scenario-labs/blender-plugin` (GPL-3.0). Behaviour comes from
  the shared Scenario specs; the code here is written for this repository.
- All network and file IO is asynchronous; Slate views never block the game
  thread. Editor-facing errors use the messages in `ScenarioErrors`.
- Tests write only to ignored folders (`Saved/`, `Intermediate/`,
  `tests/reports/`).
- Do not edit versions or `CHANGELOG.md` by hand once release automation is
  set up.
- Keep doc edits in a feature PR to the prose the change makes wrong. Test
  runs, platforms and review notes belong in the PR body, not in docs.

## Commits and pull requests

- Branch from `main`; pull requests are squash-merged, so the PR title becomes
  the commit header and the changelog line. Titles follow Conventional Commits
  with a scope: `core`, `editor`, `ui`, `agent`, `lanes`, `docs`, `tools`,
  `tests`, `ci`, `deps`, `release`, `repo`. Example:
  `fix(editor): keep the selection after placing a material`.
- Fill `.github/pull_request_template.md`; tick only what you ran.
- Screenshots of a visible change go in the PR description, never in a commit.
- Name the contributing agent in the PR and keep its co-author trailer on
  commits and in the squash message. A human reviews the complete diff before
  merge.
